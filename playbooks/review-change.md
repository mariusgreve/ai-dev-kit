# Review change

1. Read the governing spec, architecture and repository instructions.
2. Inspect the complete diff and affected call paths.
3. Run deterministic verification before semantic review.
4. Prioritize findings by correctness, security, data loss, compatibility and missing tests.
5. Give concrete file references and explain the failure scenario; avoid style-only findings already enforced by tools.
6. State explicitly when no material findings remain and identify residual verification gaps.
